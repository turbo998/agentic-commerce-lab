### 2.1 x402 Foundation（`x402-foundation/x402`，`main` 推进至 `79263af`，新增 9 项合入与关键开放 PR `#3910`）

1. **XRP Ledger 原生支付通道 `upto` 方案规范落地（commit `2b06a54` / PR `#3023`：`specs/schemes/upto/scheme_upto_xrpl.md`）**：
   - **仅接受规范数字型 CAIP-2 网络标识**：严格限定 `xrpl:0`（Mainnet）、`xrpl:1`（Testnet）、`xrpl:2`（Devnet），显式拒绝 `xrpl:mainnet` 等非规范别名（`unsupported_network`），且 V1 首版仅支持原生 `asset: "XRP"`（以整滴 `drops` 计价，$1\text{ XRP} = 10^6\text{ drops}$）并强制 `extra.areFeesSponsored == false`。
   - **链下 `CLM\0` 索赔消息签名与 `PaymentChannelClaim` 双路径**：授权载荷携带 `channelId`（64 位十六进制）、`maxAmount`（授权上限 drops）及链下索赔签名（对 `'CLM\0'` `0x434C4D00` + 32 字节 `channelId` + 8 字节大端 `uint64(maxAmount)` 签名；Secp256k1 强制 canonical low-`s`）。
   - **`/verify` 阶段严禁夹带 `settlementTransaction` 并强制全新通道与双重时间裕度**：
     - 客户端不得在 `/verify` 载荷中提交预签名的 `PaymentChannelClaim` 事务字节，否则立即返回 `invalid_upto_xrpl_payload_unexpected_settlement_transaction`；
     - 链上 `PayChannel` 账本对象必须满足 `Account == payer`、`Destination == payTo`、`Balance == "0"`（全新未使用通道，防止复用半消耗通道）、`Expiration` 未设置，且 `Amount >= maxAmount`；
     - 考虑 XRPL 共识关账时间漂移，强制 **20 秒着陆裕度（Landing Margin）**：`CancelAfter >= close_time + maxTimeoutSeconds + 20`（若设置），且 `SettleDelay >= max(maxTimeoutSeconds + 20, minSettleDelay)`。
   - **`/settle` 结算上界替换、零使用裸 `tfClose` 通道释放与 `(network, channelId)` 原子并发互斥**：
     - 校验 `0 <= settleAmount <= maxAmount`；当 `settleAmount > 0` 且 `Balance < settleAmount` 时，将 `exact` 校验规则 1 与规则 4 中的固定 `requirements.amount` 替换为 `payload.maxAmount`；
     - 当 `settleAmount == 0` 或链上 `Balance >= settleAmount` 时，Facilitator 无需索赔差额，但若广播 `tfClose`（`0x00010000`）释放付款方锁仓储备金，**必须省略 `Balance`、`Amount`、`Signature`、`PublicKey` 四个字段**（XRPL 账本拒绝同时携带索赔字段但无新增增量的关通道事务）；
     - 同一 `(network, channelId)` 同一时刻仅允许一个 `/settle` 在途，并发重复请求返回 `upto_xrpl_channel_settlement_in_progress`。
2. **无方法通配路由（`* /path`）放行 `OPTIONS` 预检与浏览器标准 CORS 头（commit `3bd3c1d` `#3738`、commit `58a5d7d` `#3809`）**：
   - 修复 TypeScript (`@x402/core`)、Python 与 Go 资源服务器中无方法前缀路由（如 `* /api/*`）将浏览器 `OPTIONS` 预检误判为需付费请求并返回 `HTTP 402` 的缺陷：当 `request.method.upper() == "OPTIONS"` 且未显式注册 `OPTIONS /path` 付费路由时，直接放行给宿主 CORS 中间件；
   - `specs/transports-v2/http.md` 新增浏览器 CORS 规范：要求暴露 `Access-Control-Allow-Headers: PAYMENT-SIGNATURE, Content-Type` 与 `Access-Control-Expose-Headers: PAYMENT-REQUIRED, PAYMENT-RESPONSE`。
3. **批量结算退款收据 Fail-Closed 校验、EVM 燃气代付 RPC 强制配置与 Paywall HTML 配置 XSS 转义（commit `470419d` `#3096`、`b5ee357` `#3459`、`9c50903` `#3889`、`a9772e5` `#3855`）**：

## 3. 辩证架构思考：Agentic Commerce AI-Native 架构 vs. 云厂商经典三层 Web / Well-Architected 框架

| 架构维度 | 经典三层 Web / 传统云 WAF 假设 | Agentic Commerce AI-Native 确定性改进（Stage 170） |
|---|---|---|
| **链下支付通道着陆裕度与 CORS 预检隔离** | 假设同步数据库扣款无区块共识时间漂移；通配符鉴权中间件拦截一切 HTTP 动词（含 `OPTIONS`） | 针对 XRPL 支付通道强制 `/verify` 禁带 `settlementTransaction`、`Balance == 0`、`CancelAfter/SettleDelay` 预留 `20s` 着陆裕度、零使用关通道使用裸 `tfClose`（x402 `#3023`）；无方法通配路由自动跳过 `OPTIONS` 预检并暴露 `PAYMENT-REQUIRED`/`PAYMENT-RESPONSE` CORS 头（`#3738`/`#3809`）；阻断 `payer == payTo` 自付刷量（`#3910`） |
| **结账状态机可恢复回退与远期订阅当期零计费** | 结账进入待提交态后只能单向成功或硬失败；订阅计划常把首期与远期账单混算进购物车总额 | `ready_for_complete` 显式支持回退 `incomplete` 或升级 `requires_escalation`（UCP `#672` `5410813`）；远期周期订阅 `schedules[]` 当期结账应付为 `0`，严禁混入当前 `totals`（`#890`）；REST 签名响应绑定请求 `@method`/`@target-uri` 防 CDN 旧价重放（`#699`） |
| **本地 MCP 代理安全注解透传与请求级快速失败** | 网关代理转发工具时仅保留名称与入参 Schema，忽略元数据且上游鉴权失败时挂起连接 | 本地 `@stripe/mcp` 代理通过 `registerTool` 原样透传 `destructiveHint`/`readOnlyHint` 注解（`stripe/ai` `#584`），并在转发 JSON-RPC Request 失败时立即合成 JSON-RPC Error 响应免除 60s 挂起（`#542`），配合 MCP `SEP-3415` 游标截断感知与 Standard Webhooks 事件订阅（`#3415`） |
| **Agent 评测分母反作弊与零内部主键泄露** | 将工具参数解析报错视作系统异常剔除样本；测试集 Prompt 偶然包含内部主键 ID | 模型生成的畸形工具参数与空白回复一律按 `AGENT_ERROR`（`0.0` 分）计入总样本分母（$\tau$-bench `#674`），且用户侧 `known_info` 严禁包含内部主键 `user_id`（`#677`） |
