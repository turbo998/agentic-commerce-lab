## Stage 1654：已验签事件不是当前支付状态

北京时间 00:05 从 Stage 1653 `6cdefcf` 恢复；00:06 起核验 Stripe
Webhook、事件 snapshot 与固定提交的 Python SDK。遵守 23:00–06:00 夜间门禁，
05:30 起不启动新阶段；本记录使用实际跨日日期，不改写 10 月 28 日历史。

详细资料：[原始字节验签与权威回读](../../docs/research/2026-10-29-stripe-delivery.md)。
本轮只新增 Stripe 证据；不把 Visa/Sierra 的既有结论包装为新的发布核验。

**技术资产：** [`lab/stripe_delivery.py`](../../lab/stripe_delivery.py) 是标准库
离线 HMAC-SHA256 参考实现；返回时间戳、body 摘要及必须回读标记，不解析事件、
不写支付状态、不去重。多 `v1`、原始字节及本地对称时钟策略均有测试；
窗口内重放仍可能通过，生产应优先使用维护中的官方 SDK。

**架构判断：** 把传输认证、持久 inbox、对象/账号绑定、权威回读与单调账本更新
分开；真实送达不等于状态新鲜、消费者同意或结算。Well-Architected 是质量与权衡
框架，不等同于 Web 三层拓扑；AI-native 工作负载需要显式的经济副作用不变量，
而非默认增加 agent 数量。

**验证范围：** 62 项针对性工程测试通过，新增 16 项方法，包含独立 .NET 固定向量、
正负时间边界及已验签成功事件仍不得关闭 `unknown` 的集成断言。
全库 3,787 项单元测试、编译、两个既有演示、24 个本地链接及双语示例均通过。
这是 `synthetic` 离线工程研究，不是模型 benchmark、真实支付验证或 SDK 认证。
README、README.en.md 与 assets/ 保持用户 `1d9273d` 内容。

未实现：真实 HTTP ingress/ACK、secret 生命周期、事件 schema/账号认证、持久去重、
真实 provider 回读与结算。它们保留为独立验收边界，不以成功形状的默认值补齐。

## Stage 1655：持久接收去重不等于支付副作用去重

北京时间 00:26 从 `0ad9a5d` 恢复，00:27 起重新核验 Stripe 重试、事件身份与
SQLite 本地原子提交。上节的未实现项描述 Stage 1654 时点；本增量仅补充接收侧的
scoped Event ID 去重，不声称实现 worker 或经济副作用 exactly-once。

[双语研究与可运行示例](../../docs/research/2026-10-29-stripe-inbox.md) |
[资产](../../lab/stripe_inbox.py) | [测试](../../tests/test_stripe_inbox.py)。
先验签再解析，可信 tenant/endpoint/account/mode 下事务化保存最小回读提示。
同一 Event 重投只保留一行；新签名/时间戳不是新身份；不同 Event ID 即使对象/type
相同也不合并。字节差异显式返回标记，type/对象关联变化则报错。

83 项针对性测试通过，新增 21 项方法；覆盖新进程读取、并发、commit 故障回滚、身份与模式隔离、
敏感数据排除及仍不得关闭 `unknown`/再次 dispatch 的集成断言。
全库 3,808 项单测、编译及两个既有演示通过。
所有记录保持待回读；没有 ACK、worker claim/完成、真实 provider 读取或支付操作。
thin/Connect/组织 context 明确不在支持范围，不把 snapshot 切片当作生产 SDK 推荐。

架构反思：成熟事件驱动系统本就需要 inbox 与业务幂等；AI-native 的区别在于
不能让重规划的模型把接收成功补全为授权、状态新鲜或支付完成。
研究为 `synthetic` 工程测试，不产生模型 benchmark；README/SVG 仍保护不变。
