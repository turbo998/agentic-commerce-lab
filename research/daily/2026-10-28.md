## 3. 辩证架构思考：Agentic Commerce AI-Native 六平面架构 vs. 云厂商经典三层 Web 架构（Well-Architected）

| 架构维度 | 云厂商经典三层 Web 架构（Presentation → Stateless App → DB） | Agentic Commerce AI-Native 六平面确定性架构（Stage 618–621） |
|---|---|---|
| **授权同意时机（Consent Timing）** | 假定人类用户在浏览器亲眼阅读 OAuth 授权页文字，将所有 Scope 视为粗粒度读写权限 | **登录前后果分级门控（Pre-Sign-In Consequence Gating）**：消费 Poppy `auth.scope_hints`（`changes: irreversible`, `personal_data: true`）与 `@stripe/mcp` 远端工具注解，在 OAuth 握手前触发确定性人类确认门禁 |
| **凭证作用域与到期淘汰** | 长期静态 `sk_live_*` 存放于环境变量，跨微服务共享全账户权限 | **硬截止期与受众降权（Hard Sunset & Token Exchange）**：强制拦截 `2026-10-31` / `2026-11-30` 后的遗留 Stripe API 密钥，要求 `rk_live_*` 委托密钥或 OAuth 2.1 + RFC 8693 `invalid_target` 边界校验 |
| **多模态 Schema 演进与技能同步** | 依赖手工维护 DTO，配置中心拉取失败时可能导致空路由或静默降级 | **捆绑 Schema 递归校验与技能缓存防清空**：对齐 UCP `#982` `allOf`/`oneOf` 分支契约校验，并在远端技能同步异常时保留最后已知完好快照（`stripe/ai#586`） |
