# 2026-10-11 Agentic Commerce 每日研究

**视角：解决方案架构师。** 本日建立可追溯研究基线，不声称今天发生了全部列出的产品发布。核验对象为公开官方资料；不包含账户准入验证、真实资金、云部署或供应商认证。

## 本日新增研究结论

| 结论 | 证据 | 对方案的影响 |
|---|---|---|
| Visa VIC 在 authenticated Payment Instruction 与网络授权控制之间建立链路 | [VIC 开发者正文](https://developer.visa.com/capabilities/visa-intelligent-commerce/overview) | 模型不能持有或放宽支付权限；Passkey、凭证获取、商户金额控制与 commerce signals 分开设计 |
| TAP 是请求信任层，不是资金结算协议 | [TAP 公告](https://corporate.visa.com/en/sites/visa-perspectives/newsroom/visa-unveils-trusted-agent-protocol-for-ai-commerce.html)、[开发者正文](https://developer.visa.com/capabilities/trusted-agent-protocol/overview) | CDN/网关验签后仍需用户授权、PSP 风控与资金状态确认 |
| Visa MCP 与 Acceptance Toolkit 公开更新描述为 pilot | [官方更新](https://corporate.visa.com/en/sites/visa-perspectives/innovation/visa-mcp-server-agent-acceptance-toolkit.html) | 开票/Pay By Link 是优先试验场景，不能据此宣称自主支付已广泛可用 |
| Stripe Suite 首发早于 Sessions 2026；SPT 在 Suite 首发文章中已经出现 | [2025-12-11 公告](https://stripe.com/blog/agentic-commerce-suite)、[2026-04-29 Sessions](https://stripe.com/blog/everything-we-announced-at-sessions-2026) | 纠正“SPT 首发于 Sessions 2026”的搜索摘要；发布与扩展分开记录 |
| ACP 当前范围比首发材料更广，当前作者列表也变化 | [首发](https://stripe.com/blog/developing-an-open-standard-for-agentic-commerce)、[当前规格入口](https://docs.stripe.com/agentic-commerce/protocols/acp) | 固定 2026-04-17 规格及后续兼容策略；不依赖 `unreleased` |
| AP2 当前主分支正文使用 Open/Closed Checkout & Payment Mandates | [官方文档](https://ap2-protocol.org/) | 不照搬老版本 Intent/Cart 命名；tag 与 main 的版本关系需再核验 |
| SPT 的 API、Link 的 OAuth、机器支付地域与币种不是同一个能力边界 | [SPT seller](https://docs.stripe.com/agentic-commerce/concepts/shared-payment-tokens.md?agent-seller=seller)、[Link](https://docs.stripe.com/agentic-commerce/agents/link-agent-wallet)、[machine payments](https://docs.stripe.com/payments/machine) | 不设计一个“通用付款 token”适配所有钱包/协议；按角色、市场与 preview version 分开确认 |
| Stripe MCP 密钥迁移有明确未来期限 | [MCP 文档](https://docs.stripe.com/mcp) | 2026-10-31 起需 OAuth 或 Agent Keys；未来每日优先跟踪迁移文档变化 |
| Stripe 框架入口已强调 Plugins/MCP/Skills，而不只是旧 Toolkit | [Agents 文档](https://docs.stripe.com/agents)、[Stripe AI](https://github.com/stripe/ai) | 计费 SDK、工具访问与付款权限分开；旧仓库名称与当前结构需要核验 |

Stripe 发布日期由官方页面 `datePublished` 读取：ACP 为 2025-09-29、Suite 为 2025-12-11、Sessions 为 2026-04-29。Visa 公告精确日期本轮未独立提取，保留待核验。研究未把“文档公开”推断为所有客户均已 GA。

## 今日开发的技术资产

| 资产 | 能力 | 边界 |

| [离线 checkout](../../lab/checkout.py) | 最终购物车绑定、商户/币种/金额限制、到期/撤销、单次授权消费、持久幂等回执与并发保护 | 仅合成数据；无数字签名、用户认证、真实 PSP 或标准 wire-format |

| [回归测试](../../tests/)与 [CI](../../.github/workflows/ci.yml) | 离线授权/并发/持久化与来源 provenance 检查 | 不声称真实支付、供应商认证或完整协议兼容 |

## 来源获取状态

本轮 web fetch 对 Visa 营销页只返回极少文本，因此关键 VIC 结论改以开发者页为据。部分 URL 初次出现传输错误，SPT seller 通过直接 HTTPS 读取，TAP README 通过 GitHub Contents API 读取，ACP/UCP 正文通过后续抓取核验。失败不解释成“没有新发布”。

机器抓取的逐源结果保存在 [当日来源快照](2026-10-11-sources.json)。该快照是获取证据，不是专家摘要；`baseline` 表示首次观测，`changed` 只表示文本变化，`error/unknown` 必须继续核验。
