## 2. Dialectical AI-Native Architecture Reflection: Consumed Replay History vs Credential Issuance

Contrasting cloud Well-Architected Frameworks (WAF) and classic 3-tier web architectures against AI-Native Agentic Commerce workloads highlights two control-plane invariants reinforced by Poppy `0.2` and Draft `0.3`:

1. **Replay-Table Lookup Is Neither a Pre-Admission Check Nor Proof of Credential Issuance**: Classic 3-tier web controllers frequently query an idempotency table before executing an action or treat a present row as proof of completion. Under AI-Native agent retries and concurrent workers, calling `is_consumed` before `consume` introduces a TOCTOU race outside `BEGIN IMMEDIATE`; conversely, `is_consumed == True` proves only that the local admission boundary burned that `jti` (so recovery after a crash or lost reply must mint a fresh `jti`), **never** that downstream token issuance succeeded or that any commerce operation was authorized.
2. **Orthogonal State Machines Across Protocol Revisions (Poppy `0.2` vs Draft `0.3`)**: Draft `0.3` separates per-request `Poppy-Session` headers from OAuth tokens and requires `503 Retry-After` while an approved `operations` v2 execution has an unknown outcome. This reinforces our core architectural separation: session assertion replay history, explicit user approval state, and payment `unknown` recovery must remain distinct deterministic state machines rather than collapsing into a single web session table.
