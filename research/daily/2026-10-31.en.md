## 6. Architecture impact and open items

1. **Execution-authority separation remains strict:** claim visibility is not external-action authority.
2. **Monitoring signal quality improved:** layered “noise filtering + selected facts” now covers both seller and connect SPT views.
3. **Cross-source validation now includes a gate:** `cross_source_checks` verifies seller/connect parity, and `mismatch` now fails the monitor run explicitly.
4. **Connect semantic integrity is now gated:** missing required Connect markers triggers `mismatch` and blocks monitor success.
5. **Parser-version parity is now gated:** seller/connect selected-facts parser drift triggers `mismatch` and blocks monitor success.
6. **Cross-source gate health is now summarized:** `cross_source_summary` exposes stable counters and a blocking flag for automation and daily reporting.
7. **Run-level blocking state is now summarized:** `gate_health` combines fetch failures, facts-parse failures, and mismatch gates into one deterministic blocking signal.
8. **Blocking reasons are now directly consumable:** `gate_health.blocking_reasons` emits fixed-order blocking classes, reducing downstream reason-inference logic.
9. **Check status is now O(1) readable:** `cross_source_statuses` provides a stable index and reduces consumer parsing divergence.
10. **Blocking routing can now consume grouped IDs directly:** `cross_source_partitions` groups check IDs by status and removes repeated downstream grouping logic.
11. **Run-level blocking checks are directly readable:** `gate_health.cross_source_blocking_checks` removes extra joins for blocker routing.
12. **Report contract is now explicitly versioned:** `schema_version` provides a stable compatibility anchor for consumer parsers.
13. **Fetch-health telemetry is now directly summarized:** `observation_summary` reduces downstream full-array scans for run-level status.
14. **Fetch partitions are now directly routable:** `observation_partitions` exposes source-ID lists for changed/unknown/error classes.
15. **Blocker sources are now run-level readable:** `gate_health` now carries `observation_error_sources` and `policy_error_sources`.
16. **Unified blocker set is now directly consumable:** `gate_health.blocking_sources` provides a deduplicated blocker source-ID union.
17. **Blocking dimensions are now directly consumable:** `gate_health.blocking_dimensions` provides per-dimension source/check object lists.
18. **Blocker state is now single-value comparable:** `gate_health.blocking_fingerprint` enables stable gate-state change detection.
19. **Fingerprint contract is now explicitly versioned:** `gate_health.blocking_fingerprint_version` fixes comparison semantics to `sha256-json-v1` for downstream consumers.
20. **Blocking state ID is now directly consumable:** `gate_health.blocking_state_id` carries both version and digest, reducing downstream join/composition logic.
21. **Blocking-state transition is now directly consumable:** `gate_health.blocking_state_transition` provides baseline/unchanged/changed semantics without extra snapshot joins.
22. **Prior checkpoint timestamp is now directly consumable:** `gate_health.blocking_state_previous_checked_at` identifies the exact prior snapshot timestamp used for transition derivation.
23. **Prior report date is now directly consumable:** `gate_health.blocking_state_previous_report_date` provides a direct `YYYY-MM-DD` anchor for daily-partition routing.
24. **MCP deadline simulation is now source-provenance-aware:** `lab.mcp_migration` can optionally consume daily `stripe-mcp` selected facts and emits `deadline_source/deadline_parser_version` for auditable boundary changes.
25. **Poppy publication gate unchanged:** production implementation remains anchored to published `0.2` until `0.3` is formally published.
