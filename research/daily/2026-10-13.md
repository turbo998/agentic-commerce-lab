### MCP 迁移：18 个日历日，不是服务器倒计时

10-13 到 10-31 相差 **18 天**。官方明确从 10-31 起拒绝 full-access secret keys / 没有 Agent tag 的 restricted keys，响应 `401` 并给 OAuth discovery challenge；仍未给具体时刻/时区。交互客户端用 OAuth，不能 OAuth 的 autonomous client 新建最小权限 Agent Key，先 sandbox 验证再 expire 旧 key。

这只针对 **Stripe MCP**：不能把该限制套到 UCP `/tokenize` 的 server-side agent API key 或 Link 的客户 OAuth。Agent tag 不能从 key 名称/prefix 推断。账户负责人需核验读写/approval rules、环境和撤销范围；401 不能触发高权限回退。本地盘点更新 `policy_checked_on=2026-10-13`，没有创建、轮换或撤销实际 key。

## 4. AI Native 架构：从工具可用到交易可执行

**不是取代 WAF，也不是给 Web 三层加更多 Agent。** [官方 WAF AI design](https://learn.microsoft.com/en-us/azure/well-architected/ai/application-design)已有 Client / Intelligence / Inferencing / Knowledge / Tools 五层、工具自身策略和“先确定性编排，再在不足时引入 Agent reasoning”。N-tier 是架构风格，WAF 是质量属性/取舍框架；它们不是同一比较对象。今天也读取 Azure WAF MCP 的只读工具说明，不涉及资源操作；具体事实来自官方正文。

今日领域补强为四道不同门槛：**发现宣告 → 本地可执行兼容候选 → 最终消费者授权 → provider 可信结果**。主张与取舍如下；这是本研究的设计建议，不是厂商认证要求：

| 需要重新思考的对象 | 为什么通用工具接入/三层划分不足 | 保留什么，增加什么 |
|---|---|---|
| 可执行契约 | 商户宣告 Link/Google Pay 不代表选定 handler `/complete` 接受；exact version 匹配也不证明已审阅 | 保留 adapter/anti-corruption layer；增加按 protocol/handler/instrument/endpoint 的能力交集及未知版本拒绝。白名单过窄降低覆盖率，但比猜测互操作安全 |
| 身份与交易授权 | MCP OAuth/Agent Key、Link customer token、UCP `identity.access_token` 的 seller profile ID 语义不同 | 保留 IAM/最小权限；typed identity/context，broker 不让 LLM 混用。商业关系和环境匹配仍不产生客户同意 |
| 非确定性与副作用 | Agent 可以探索、多轮重试，但扣款、refund、发票创建不能由推理投票批准 | 知识/推理面提出请求，确定性 authority 面消耗可信批准，经济状态/证据面持久化 outcome；可逻辑分层，先模块化单体 |
| 开发指导更新 | 自动更新 skills/plugin 可能改变反馈建议或 API 升级指导，不等于应用与 endpoint 兼容已更新 | 固定部署的 model/prompt/tool/schema/revision；指导内容作为参考，不自动改权限或上传业务数据。API preview pin 独立于 plugin version |
| 失败恢复 | 文档说 retryable 不是准许 Agent 更换卡、金额、商户或支付 key 重付 | 保留幂等/outbox/saga；`requires_action` 独立等待客户操作，`unknown` 查询对账；token expired 重新获取凭证前仍校验批准范围 |
| 正确性与 SLO | 网关 200、MCP 调用成功、模型答复“已买”均不证明正确完成 | 同时衡量服务可用性、授权约束符合率、正确交易完成率及重复经济副作用；再分别测 quote/人工等待/payment/fulfillment 时间 |
| 数据与成本 | 对话缓存不是真实库存、付款账本；token 少不等于低交易风险 | 读缓存绑定身份/策略/版本，成交前回查最终税费/运费/条款；分别设置推理、工具与累计消费预算 |

今日可离线检验的只是**可执行兼容候选**门槛，不伪装成四门全覆盖。即使 `candidate_unverified`，用户同意、实际商户配置、credential scope、地区/账户准入、签名验证和 provider outcome 都未验证。不存在自动从不支持 Link 切到 PAN/form fill 的 fallback；这会改变 PCI 边界和用户批准路径。

Stripe skill 的反馈建议变化还体现“外发信息也是副作用”：发现公开指导建议反馈，并不授权发送内部材料、源码、个人信息或凭证。本轮没有执行 feedback 工具，也不复制第三方 skill 到仓库。
