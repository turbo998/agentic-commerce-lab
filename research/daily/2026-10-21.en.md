## 2. Primary-Source Protocol & Repository Audit Findings (Stage 116)

### 2.1 Agentic Commerce Protocol (`agentic-commerce-protocol/agentic-commerce-protocol`)
1. **PR `#316` (commit `2b2f2dd`, `2026-10-21T15:12:30Z`): `SEP #303: UserApproval and approval_digest bind what the user approved to the checkout (Section 4.4a, rule 4)`**:
   - **Problem Statement**: When an agent orders an item or variant that diverges from what the user approved (e.g., user approved `TEE-01` `variant: "green"`, agent ordered `variant: "black"`), a post-hoc platform statement cannot prove what was approved at checkout time, while a traditional chargeback unfairly penalizes the merchant who fulfilled exactly what the agent confirmed.
   - **Cryptographic Checkout Binding & Two-Part Admissibility Check (Section 4.4a)**:
     - Defines `UserApproval` with `items[]` (required non-empty `sku`, integer `quantity >= 1`, optional `variant`), `approved_at` (RFC 3339 timestamp), and `approval_digest` (`^[0-9a-f]{64}$` lowercase hex SHA-256 over the RFC 8785 JCS canonical form of `{items, approved_at}`).
     - Adds optional `approval_digest` to `CheckoutSessionCompleteRequest.dispute_resolution` so the merchant holds the digest before any dispute exists.
     - Adds optional `user_approval` to `DisputeRecord`. The dispute provider MUST recompute the RFC 8785 JCS SHA-256 digest of `{items, approved_at}` AND verify that it equals both `user_approval.approval_digest` and the `approval_digest` committed on checkout completion. Only a `user_approval` passing both checks is admissible evidence; otherwise it is treated as a unilateral platform statement.
   - **Intent-Conflict Attribution (Section 7.4 Rule 4)**: When an admissible `user_approval` conflicts with the disputed order's `sku`, `variant`, or `quantity`, it is recorded as an `intent` conflict finding against the **agent platform (`agent_platform`)** without reversing the merchant's charge (`merchant_charge_reversed = False`).

### 2.2 Universal Commerce Protocol (`Universal-Commerce-Protocol/ucp`)
1. **Merged PR `#891` (`f2626c2`, `2026-10-20T15:44:18Z`), `#975` (`5118ace`), and `#978` (`b8b8985`) on `main`**:
   - Lands RFC 9728 `authorization_servers` issuer rules and multi-entry identity discovery on `main`.
2. **PR `#540` (commit `207314b`, `2026-10-21T06:56:52Z`): `com.merchantstamp.mandate-evaluation` AP2 Admission-Only Mandate TTL & `/.well-known/ucp` `keys[]` Discovery**:
   - **Evaluate-Once-at-Admission**: AP2 mandate liveness (`evaluated_at <= mandate_exp`) is evaluated **exactly once** at admission of `Complete Checkout`. Once admitted (`result == "VALID"`), authorization is frozen for the execution of Complete Checkout — `complete_in_progress` MUST NOT abort mid-flight with `mandate_expired` even if `completed_at > mandate_exp`. If expired at admission (`evaluated_at > mandate_exp`), checkout transitions to `canceled` with `mandate_expired`.
   - **Unified Key Discovery (`207314b`)**: Drops separate `signing_keys[]` wording and references the AP2 Mandates cryptographic requirements (`keys[]` in `/.well-known/ucp`, ES256 required, RFC 8785 JCS canonicalization).
3. **PR `#966` (`2026-10-21T07:45:13Z`): `dev.ucp.shopping.policy.return` Explicit Return Eligibility, Business-Stated `expires_at`, and Typed `fees[]` Ceilings**:
   - Requires explicit `eligibility` (`window` | `unlimited` | `not_accepted`; omitted $\neq$ unlimited), business-stated `expires_at` (platforms MUST NOT compute dates from `duration` + `anchor`; anchors restricted to `purchased` | `fulfilled` | `delivered`), and typed `fees[]` ceilings that the business MUST NOT exceed.

## 3. Dialectical Architecture Comparison: AI-Native vs. Cloud 3-Tier Web / Well-Architected

| Dimension | Cloud 3-Tier Web / WAF Assumption | Agentic Commerce AI-Native Guardrail (Stage 116) |
|---|---|---|
| **User Approval & Dispute Liability** | Human checkout click equals intent; disputes reverse merchant charges | Commit `UserApproval` RFC 8785 JCS SHA-256 `approval_digest` at `Complete Checkout` (ACP `#316`); attribute post-admission intent conflicts to `agent_platform` without reversing the merchant's charge |
| **Mandate TTL & Return Deadlines** | Re-check session expiry at every internal hop; compute return windows in UI | Evaluate AP2 mandate TTL **once at admission** and freeze across `complete_in_progress` (UCP `#540` `207314b`); enforce explicit return `eligibility` and business-stated `expires_at` (UCP `#966`) |
| **Paywall & Response Provenance** | HTTP 200 implies valid delivery; router and middleware path decoding assumed identical | Verify `x402` `response-provenance` 5-member JCS SHA-256 fixed point with no-collapse outcomes (`#3304`), escape `<` in inline paywall JSON (`#3855`), and match raw + decoded paths against `%2F`/`%5C` bypass (`#3857`) |
| **Knowledge Sandbox Isolation** | Regex command-string filtering prevents file escapes | Quoted `python3 -c` strings bypass regex; enforce minimal env allowlists + secret scrubbing ($\tau$-bench `#653`) and root-walk `denyRead` allowlist emulation (`#655`) |
